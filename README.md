# Logistics Nexus — Multilingual Hybrid-RAG Chatbot

A locally-hosted Retrieval-Augmented Generation (RAG) assistant for logistics/supply-chain documents. It ingests PDFs, spreadsheets, CSVs, text, and scanned images into a hybrid (dense + sparse) vector index, then answers natural-language questions — in any language — grounded in that data, through a terminal-styled web chat UI.

## Features

- **Multi-format ingestion** — PDF, CSV, XLSX, TXT/MD/JSON, and images (via OCR) are all routed through format-specific loaders.
- **Hybrid retrieval** — combines dense embeddings (`nomic-embed-text-v1.5`) with sparse SPLADE embeddings for keyword + semantic recall in a single Qdrant collection.
- **Lightweight entity extraction** — regex-based extraction of product IDs, acronyms, and emails, attached as metadata on each chunk for future graph-style lookups.
- **Multilingual queries** — incoming questions are language-detected and translated to English for retrieval, then the answer is translated back to the user's language.
- **Fully local inference** — answers are generated by a local Ollama model (`llama3.2`); no data leaves the machine at generation time.
- **Web UI** — a retro terminal/HUD-themed chat interface (Flask + vanilla JS/CSS).

## Architecture

```
data/ (pdf, csv, xlsx, txt, images)
      │
      ▼
  ingest.py  ──  load → chunk (1000/200 overlap) → extract entities → embed (dense + sparse)
      │
      ▼
  Qdrant ("logistics_db" collection, hybrid mode)
      │
      ▼
  logistics_agent.py  ──  detect language → translate → retrieve top-k → build prompt → Ollama (llama3.2) → translate back
      │
      ▼
  server.py  ──  Flask API (POST /chat)  ──  templates/index.html + static/ (chat UI)
```

## Tech stack

| Layer               | Technology                                            |
|----------------------|-------------------------------------------------------|
| LLM (generation)     | Ollama, `llama3.2` (local)                            |
| Dense embeddings     | `nomic-ai/nomic-embed-text-v1.5` via FastEmbed         |
| Sparse embeddings    | `prithivida/Splade_PP_en_v1` via FastEmbed             |
| Vector store         | Qdrant (hybrid dense+sparse search)                    |
| Orchestration        | LangChain (community loaders/splitters, manual retrieval + prompting) |
| Language detection   | `langdetect`                                          |
| Translation          | `deep-translator` (Google Translate backend)          |
| Backend              | Flask + Flask-CORS                                    |
| Frontend             | HTML/CSS/JS (no framework)                             |
| Document loaders     | `pypdf`, `unstructured`, `pandas`/`openpyxl`, `pytesseract` |

## Prerequisites

- **Python 3.10+**
- **Docker**, for running Qdrant
- **[Ollama](https://ollama.com)**, with the model pulled locally:
  ```bash
  ollama pull llama3.2
  ```
- **Tesseract OCR** installed on the system (required for image ingestion via `pytesseract` / `UnstructuredImageLoader`)

## Setup

1. **Clone and install dependencies**
   ```bash
   git clone https://github.com/d-anchu/RAG-AI-AGENT-.git
   cd RAG-AI-AGENT-
   python -m venv venv
   source venv/bin/activate  # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```

2. **Start Qdrant**
   ```bash
   docker run -p 6333:6333 qdrant/qdrant
   ```

3. **Start Ollama** (if not already running as a service) and confirm the model is available:
   ```bash
   ollama list
   ```

4. **Add your documents** to the `data/` folder (PDF, CSV, XLSX, TXT, MD, JSON, or images).

5. **Run ingestion** to build the vector index:
   ```bash
   python ingest.py
   ```
   This wipes and rebuilds the `logistics_db` collection each run.

6. **Start the app**
   ```bash
   python server.py
   ```
   Visit `http://localhost:5000`.

   Alternatively, test retrieval from the terminal without the web UI:
   ```bash
   python logistics_agent.py
   ```

## Configuration

Runtime settings currently live as constants at the top of `ingest.py` / `logistics_agent.py`:

| Variable          | Default                  | Meaning                          |
|-------------------|---------------------------|-----------------------------------|
| `QDRANT_URL`      | `http://localhost:6333`   | Qdrant endpoint                   |
| `COLLECTION_NAME` | `logistics_db`            | Qdrant collection name            |
| `OLLAMA_MODEL`    | `llama3.2`                | Local model used for generation   |
| `DENSE_MODEL_NAME`| `nomic-ai/nomic-embed-text-v1.5` | Dense embedding model      |
| `SPARSE_MODEL_NAME`| `prithivida/Splade_PP_en_v1` | Sparse embedding model         |

`server.py` reads `PORT` and `FLASK_DEBUG` from the environment:
```bash
PORT=8080 FLASK_DEBUG=1 python server.py   # custom port + Flask debug mode on
```
Debug mode is **off by default** — Flask's interactive debugger can execute arbitrary code if the server is ever reachable beyond localhost, so only enable it for local development.

## Known limitations

- **Manual retrieval, not a LangChain chain.** Retrieval and prompt construction in `logistics_agent.py` are done by hand rather than via a `RetrievalQA`-style chain, by design, to avoid a chain incompatibility encountered during development.
- **`ingest.py` is destructive.** Every run deletes and recreates the Qdrant collection — there's no incremental "add documents" path yet.
- **Translation depends on an unofficial, free Google Translate wrapper** (`deep-translator`), which can rate-limit or fail under heavy use; failures now fall back to the original-language text.
- **No dependency version pins** in `requirements.txt` — consider pinning versions before long-term/production use, since LangChain's package layout has changed across versions.
- **OCR quality depends on Tesseract** being installed correctly on the host system; scanned/handwritten documents may need image pre-processing for good results.
